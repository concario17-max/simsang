# 화풍수지 정리글의 사이트 적용 분석

## 제안

기존 독서 화면에 **쉽게 읽기 / 본문·번역 / 학습만화 / 사색 노트**를 둔다. 이번에 만든 492개 정리글은 쉽게 읽기에 연결하고, 본문·번역은 현재 내용을 유지한다. 만화가 없는 항목도 정리글로 먼저 공개할 수 있다. 별도 학습 사이트나 합본 다운로드 화면을 주된 독서 경로로 만들 필요는 없다.

이 문서는 적용 방안이다. 사이트 소스와 운영 데이터는 이번 분석에서 변경하지 않았다.

## 확인한 자료

- 운영 사이트의 기타 제2장 47절 해설, 제6장 5절 해설, 화 긍정편 1번 본문 화면을 직접 열어 확인했다.
- 기타 제16장 1~3절의 해설 구조도 로컬 데이터에서 확인했다.
- 로컬 독서 화면, 마크다운 표시기, 목차, 검색 색인 생성 코드와 기존 검증 항목을 읽었다.
- 정리글 492개의 분량과 표 사용 여부를 확인했다. 평균 약 414자, 범위 316~2,137자이며 제목과 마크다운 기호를 포함한 수치다. 표가 있는 항목은 17개다.

비교 화면:

- [기타 2장 47절 해설](https://simsang.org/reader/?book=gita&verse=2.47&view=commentary)
- [기타 6장 5절 해설](https://simsang.org/reader/?book=gita&verse=6.5&view=commentary)
- [화 긍정편 1번 본문](https://simsang.org/reader/?book=introspection&verse=fire.positive.001&view=text)

## 기타에서 가져올 읽기 방식

기타의 장점은 본문과 해설을 같은 항목 안에서 전환할 수 있다는 점이다. 해설은 아이콘이 붙은 주제, 짧은 설명, 비유와 비교표로 이어진다. 제2장 47절은 행동과 결과의 관계를 비교하고, 제6장 5절은 개념의 차이와 대응 단계를 나누어 보여 준다. 긴 문단을 읽기 전에 이해의 기준을 얻을 수 있다.

화풍수지에는 이 구성 원리를 적용한다. 소제목 앞의 아이콘, 친구에게 설명하는 말투, 필요할 때만 쓰는 표와 관계도는 이미 정리글에 있다. 키워드 줄이나 마지막 핵심요약, 고정된 칸 수를 모든 항목에 덧붙이면 같은 설명을 반복하게 된다. 현재 원고를 화면에 알맞게 표시하는 것이 먼저다.

기타의 해설에는 해당 구절을 넘어서는 교리 해석과 비유도 포함되어 있다. 따라서 기타의 해설을 화풍수지 내용의 검증 기준으로 삼거나 용어 체계를 섞지는 않는다. 읽기 구조를 참고하고 화풍수지의 영·혼·육체, 원소적 균형, 내관, 아카샤 등은 그 자료의 맥락으로 설명한다.

## 현재 적용을 막는 부분

현재 introspection 데이터는 499개 읽기 항목으로, 학습 대상 492개와 번역·편집 부록 7개로 구성된다. 모든 commentary가 비어 있다. reader.js는 reflection 자료에서 commentary 보기를 text로 돌리고 해설 버튼을 무조건 숨긴다. 따라서 정리글을 commentary에 넣기만 해도 실제 탭에서는 읽을 수 없다.

자료 파일과 사이트 연결 상태도 구별해야 한다. 로컬 데이터에 만화가 연결된 항목은 지 긍정편 1~6번뿐이며 각 3장이다. 기존 화 긍정편 그림 파일들이 output/imagegen에 있다는 사실만으로 사이트에 공개되는 것은 아니다. 화 긍정편 1번 운영 화면에도 현재 학습만화 준비 중으로 표시된다. 새 만화 생성 여부와 기존 만화 연결 여부를 별도 관리해야 한다.

## 권장 화면

상단은 항목 제목과 책갈피, 그 아래 네 가지 읽기 방식을 둔다.

    화 · 긍정편 1. 의지, 힘, 역량             ☆ 책갈피

    [쉽게 읽기] [본문·번역] [학습만화] [사색 노트]

    ⚖️ 바라는 마음과 실제로 해내는 힘은 달라
    짧은 구어체 설명
    필요한 경우에만 비교표

    🧘 먼저 자신을 다스리는 데 써
    짧은 구어체 설명

    🎻 몸은 영의 뜻을 표현하는 도구야
    관계 설명

    [본문·번역 읽기]       [학습만화 보기]
    ← 이전                          다음 →

새로운 사용자에게는 쉽게 읽기를 첫 화면으로 권한다. 이미 view가 명시된 주소, 사용자가 마지막으로 선택한 보기, 검색 결과의 목적 화면은 존중한다. 부록이나 정리글이 없는 항목은 본문·번역으로 연다. 다음 항목으로 이동할 때 선택한 보기를 유지하고, 기록과 책갈피의 항목 ID는 바꾸지 않는다.

쉽게 읽기라는 탭 이름만으로도 원문과 구분할 수 있다. 본문 안에 제작 날짜, 친구에게 설명하는 원고라는 부제, 매번 반복되는 출처 안내는 넣지 않는다. 정리 과정의 해석 차이는 별도의 편집 기록에서 추적한다.

모든 글을 카드로 잘게 나누거나 아코디언으로 접지 않는다. 한 항목은 연속된 짧은 글로 읽고, 아이콘 소제목과 여백으로 리듬을 만든다. 화면 본문은 읽기 쉬운 일반 글꼴로 유지한다. 손글씨체는 만화의 시각 기준이며 사이트의 긴 글까지 강제할 필요는 없다.

## 적용 방법의 비교

| 방법 | 판단 |
|---|---|
| 기존 본문을 요약으로 교체 | 한국어 번역과 정리의 역할이 섞이므로 권하지 않는다. |
| 본문 앞에 요약 전체를 항상 붙임 | 항목이 길어지고 이미 읽은 설명을 반복해서 지나가야 한다. |
| 기존 해설 자리를 쉽게 읽기로 사용 | 같은 항목 안에서 전환하고 기존 검색·기록 구조를 활용할 수 있어 권장한다. |
| 별도의 요약 전용 사이트나 목록 생성 | 목차와 읽기 기록이 분산되므로 현재 단계에서는 필요하지 않다. |

## 데이터와 동작 설계

개별 Markdown 파일을 정리글의 편집 기준으로 두고, 가져오기 스크립트로 각 항목의 commentary 문자열에 반영하는 방법이 가장 단순하다. 별도 summary 필드와 새로운 검색 경로를 동시에 추가하지 않아도 된다. 사용자 화면에서만 화풍수지의 commentary 이름을 쉽게 읽기로 바꾸고 내부 view=commentary 주소는 재사용한다.

가져올 때 항목 ID와 개별 파일을 일대일로 대응시킨다. 파일의 첫 제목은 화면의 기존 항목 제목과 중복되므로 제거하고, 소제목만 렌더링에 맞게 조정한다. 현재 마크다운 표시기는 #를 h3, ##를 h4로 변환하므로, 쉽게 읽기 안의 첫 소제목이 화면의 항목 h2 다음에 h3로 이어지도록 정규화하면 된다. 다른 책의 마크다운 규칙은 그대로 둔다. 본문은 HTML로 미리 붙이지 말고 기존의 이스케이프가 적용되는 표시기를 사용한다.

reflection 자료라는 이유만으로 해설을 숨기는 조건을 바꾸어, 정리글 유무를 기준으로 쉽게 읽기를 표시한다. 부록은 현재의 번역 검토 자료로 유지한다. 같은 reader가 다른 문헌에도 쓰이므로 책을 전환했을 때 탭의 이름과 표시 상태가 정상인지 확인한다.

현재 항목 검색과 통합 검색은 commentary를 읽는 기반이 이미 있다. 다만 reflection의 강제 전환 조건 때문에 정리글 검색 결과가 본문으로 돌아갈 수 있다. 정리글에서만 나오는 단어를 찾았을 때 쉽게 읽기로 정확히 열리고 강조되도록 결과의 보기 정보도 확인해야 한다.

독서 위치 저장 코드와 공통 읽기 진행 기능은 text/commentary를 인식한다. 내부 이름을 재사용하면 연결하기 쉽지만 새 문단 구성 때문에 예전 문단 위치가 달라질 수 있다. 본문 ID와 노트 키는 보존하고 새 정리글의 읽기 위치를 따로 관리한다.

목차에는 준비 중이라는 배지를 늘리기보다 **쉽게 읽기 · 본문**을 기본으로, 이미지가 연결된 항목에만 **만화**를 보탠다. 제공 수치에는 학습 항목 492개와 부록을 구별한다. 요약글은 이미 짧으므로 목차에 모든 항목의 요약을 다시 노출할 필요는 없다.

모바일에서는 아이콘 소제목이 줄바꿈되어도 문장과 붙지 않게 여백을 둔다. 표는 가능한 한 두 열 비교로 줄이고, 넓은 표가 필요하면 표 영역만 가로 스크롤되게 한다. 현재 원고의 표는 17개뿐이므로 일괄 표 변환은 하지 않는다. 탭 네 개의 초점·눌림 상태, 큰 글자와 야간 배경도 함께 확인한다.

## 내용 편집상 고려

이번 정리글은 단순 축약뿐 아니라 현대적인 적용 해석을 포함한다. 타인의 질병·가난·고통을 전부 업보로 단정하지 않거나, 위험 신호에 대응하도록 바꾼 부분 등이 있다. 이를 원저자의 정확한 문장처럼 본문·번역에 넣어서는 안 된다. 쉽게 읽기에 별도로 제공하고, 기존 all-chapters-editor-review.md의 차이 기록을 유지하는 이유다.

본문 안에 매번 긴 제작 설명을 넣지는 않는다. 필요한 사람을 위한 자료 안내나 편집 기록 링크를 한 곳에 두는 정도가 적절하다. 정리글 전체에 새로운 교리나 부가 해석을 일괄 추가하는 작업은 이번 적용 범위에서 제외한다.

## 실제 적용 순서

먼저 화 긍정편 1~3번으로 같은 독서 화면에서 쉽게 읽기 전환을 만들고, 긴 글·표·짧은 글의 표시를 확인한다. 새 항목 ID나 새 노트 저장 공간은 만들지 않는다.

그다음 같은 경로로 나머지 정리글을 넣어 492개 대응과 부록 7개 제외를 검사한다. 검색 색인을 재생성하고 정리글에서만 나오는 단어의 검색 이동, 공유 주소, 이전·다음, 책갈피·노트, 읽던 위치를 검증한다. 기존 체크 명령 npm run check와 데스크톱·모바일 화면 확인을 마친 뒤 배포한다.

새 만화는 생성·검토를 마친 항목부터 기존 comics 배열에 연결한다. 정리글 업데이트와 만화 공개를 묶어서 기다릴 이유는 없다. 기존 그림 파일을 모두 연결하거나 교체하는 일은 별도 범위로 판단한다.

## 변경할 파일 범위

- reader/index.html: 화풍수지 읽기 방식 이름과 표시 순서를 적용할 수 있는 구조.
- reader/reader.js: 쉽게 읽기 가용성·첫 보기·부록 처리·검색 이동·전환.
- reader/reader.css: 소제목 여백, 표와 모바일 읽기.
- introspection/index.html 및 introspection.js: 제공 내용과 목차 링크.
- scripts의 정리글 가져오기 도구: 492개 파일의 ID 대응과 제목 정규화.
- data/books/introspection.json: 각 항목의 commentary만 가져오기.
- data/search: 기존 build:discovery 절차로 갱신.
- introspection/CONTENT.md: 별도 요약·해설을 만들지 않는다는 기존 설명을 새 제공 범위에 맞게 갱신.
- tests: 이번에 바뀌는 보기 전환·부록·검색 연결을 검증하는 필요한 항목.

현재 단계의 결론은 **화풍수지에 쉽게 읽기를 추가하고, 같은 항목의 본문·만화·기록으로 이어지게 하는 것**이다.
